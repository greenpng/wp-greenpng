# ADR-0001: 记录架构决策的方式

- 状态：已接受
- 日期：2026-09-09

## 背景

greenpng 的参考项目 wp-plug 有 46 份文档，但同一系统的关键事实（表数量、函数数量、页面映射）在不同文档间互相矛盾，且无决策溯源，导致无法判断哪个版本是"当前决定"。

## 决策

用轻量 ADR（Architecture Decision Record）记录重要决策：

- 存放在 `docs/adr/`，文件名 `NNNN-kebab-case.md`，编号递增，**只新增不修改**。
- 每份含：状态（提议/已接受/已废弃/被取代）、日期、背景、决策、后果。
- 决策被推翻时，新增一份 ADR 标记旧 ADR 为"被 ADR-XXXX 取代"，不删旧文件。
- 以下变更必须有 ADR：数据表增减、对外承诺范围变化、依赖引入、许可证变化、性能预算调整、安全默认值变化。

## 后果

- 决策可追溯；文档冲突时可按 ADR 时间线仲裁。
- 成本：每个重要决策多写半页纸。
