## 3. Agy 原型代码审计：已确认缺陷清单（不可移植原因）

以下缺陷均经源码核实，附文件位置。greenpng 的正确做法见 `10-security-engineering.md`。

### 3.1 安全缺陷（高危）

| # | 缺陷 | 位置 | 后果 |
| :--- | :--- | :--- | :--- |
| S1 | `get_client_ip()` 无条件信任 `CF-Connecting-IP` / `X-Real-IP` / `X-Forwarded-For` | `core/class-agy-network-util.php` | 攻击者伪造请求头即可**绕过全部 IP 封禁与登录限流**，还能伪造他人 IP 实施封禁诬陷 |
| S2 | `?agy_test_runner=1` 公开测试端点 | `agy-suite.php:48-54` | 匿名访客可触发 1,350 行测试脚本，向全部 13 张表写入/删除数据。**未鉴权的数据操纵端点** |
| S3 | API token 明文存 `wp_options` | `integrations/capi/class-agy-universal-capi-gateway.php` | 数据库导出/备份即泄露 Meta/GA4/TikTok 密钥 |
| S4 | 未配置凭据时用 `mock_*` 默认值并让调用**静默返回成功** | 同上 | 站长以为 CAPI 在正常工作，实际什么都没发。测试"通过"的根因 |
| S5 | JS 用 `innerHTML` 拼接攻击者可控数据（UA、payload） | `preview/.../assets/js/agy-datagrid.js` | 后台存储型 XSS 管道 |
| S6 | WAF 无管理员逃生通道说明，且早期 `exit` | `security/class-agy-firewall.php` | 误杀即全站 403，无恢复手段 |

### 3.2 WAF 规则集误杀（设计性错误）

`Firewall::inspect_payload()` 对**每个请求的 GET+POST 全量参数**跑约 30 条正则，以下规则会产生大规模误报：

- 拦截 `wp-config.php` 字样 → 用户搜索"wp-config 教程"即 403
- 拦截 `<?php`、`eval(`、`system(` → 任何代码分享/教程类内容无法提交
- 拦截 `0x[0-9a-fA-F]{4,}` → 含十六进制的表单（色号、哈希、订单号）被拦
- 拦截 `../` → 合法相对路径、面包屑参数被拦
- 拦截 `document.cookie` / `javascript:` → 技术博客评论被拦
- `?author=<数字>` 返回 403 → **WordPress 核心作者归档页的官方 URL 结构被当成攻击**

**结论：WAF 规则必须重写为"仅对特定高风险参数、结合上下文、默认仅记录不拦截"的模式。** 详见 `10-security-engineering.md`。

### 3.3 性能缺陷（共享主机上不可接受）

| # | 缺陷 | 位置 | 后果 |
| :--- | :--- | :--- | :--- |
| P1 | `record_hit()` 每次页面浏览执行 `CREATE TABLE IF NOT EXISTS` | `traffic/class-agy-live-traffic-tracker.php` | 每个前台请求多发一条 DDL |
| P2 | `agy_traffic_hits` 除主键外**零索引**，却按 `created_at`、`is_bounce` 做统计查询 | 同上 | 数据量增长后仪表盘全表扫描 |
| P3 | 实时访客数用"读-改-写单个 transient 数组"实现 | 同上 `ping_live_visitor()` | 并发丢失更新；无对象缓存的站点上每 hit 写一次 `wp_options`，高并发下成为写热点 |
| P4 | 全部 13 张表用裸 `CREATE TABLE` 而非 `dbDelta()`，无 `charset_collate`，无版本号 | `core/class-agy-kernel.php` 等 | 无升级迁移路径；utf8mb4 依赖服务器默认配置，多字节内容可能乱码 |
| P5 | FCrDNS 用 `@gethostbyaddr()` 在请求路径上同步执行 | `security/class-agy-spider-detector.php` | DNS 解析无超时控制，慢解析器直接拖垮前台渲染 |

### 5.2 架构过度设计判定

文档 26 的六层企业架构（PSR-11 DI 容器 + 反射自动装配 + 不可变事件 DTO + 中间件管道 + 端云双轨）**对免费 WordPress 插件是错误的架构**：

- **DI 容器没有消费者**：每个接口恰好一个实现，无测试替换需求，且 `Agy_Kernel::instance()` 本身是单例——用单例持有容器，正是 DI 要消除的模式。提供的容器代码还有循环依赖检测缺陷（未绑定类绕过 `$resolving` 栈）。
- **自建事件总线重复 WP 原生机制**：`do_action`/`apply_filters` 已是全局优先级发布订阅。自建总线让第三方开发者无法用自己已知的 API 扩展插件，且失去 Query Monitor 等调试工具的可观测性。
- **反射自动装配在 WP 无编译缓存**：每个请求实例化 100+ `ReflectionClass`，是纯开销。
- **中间件管道从未被实现**（三个中间件只有名字没有代码）。
- **Pre-WAF 设计危险**：`plugins_loaded` 优先级 0 处 `exit()`、每次请求把整个封禁文件读入内存做子串匹配（hex 串跨记录误匹配）、写入 `wp-content/uploads`（多数主机可备份同步且部分只读）。

**greenpng 采用显式构造的三层架构**，详见 `02-architecture-blueprint.md`。

### 5.4 不可信声明（红旗清单，节选）

以下声明经核查为虚构或方法学无效，**greenpng 文档与 UI 中禁止出现此类表述**：

- "83 函数单次耗时 0.34~1.81 μs"（文档 44/41）——`hash('sha256')` 一次调用都超过此量级
- "MMDB 解析 2 微秒 / 0.08 毫秒 / 0.18ms"（四个文档四个数字，相差 100 倍）——纯 PHP Reader 实际 50~500 μs
- "探针 0ms TBT"（文档 28）——Canvas 双渲染 + WebGL 上下文创建 + 音频渲染是 5~40ms 主线程工作，TBT 定义上不可能为 0
- "188/188、158/158、35/35 全部 PASS"（多份文档）——无 CI、无断言框架、测试脚本路径指向不存在的目录、且运行环境是不存在的 "WordPress 7.1"
- "Brave 指纹噪点检测 `snap1 !== snap2`"（文档 28）——Brave farbling 按会话+站点确定性生成，同页两次读取必然相同，该检测器永远返回 false
- "服务端 Set-Cookie 不受 ITP 限制，保证 30-90 天归因"（文档 28/44）——ITP 2.3+ 与 Safari 16.4+ 规则下此承诺不成立
- "100+ 适配器懒加载 ≤0.5MB"（文档 26）——同一页的代码是急切实例化全部适配器
- "156 款插件兼容"（文档 27）——实际只有约 20 款有 Hook 清单，4 款有适配器骨架，其余 130+ 无任何实现细节

## 6. 第三方 API 计划评估

完整审计见 `07-third-party-apis.md`。要点：

| API | 判定 | 关键原因 |
| :--- | :--- | :--- |
| Cloudflare Turnstile | ✅ v1 收录（默认关闭） | 真免费、最隐私友好、需站长凭据 |
| GA4 Measurement Protocol | ✅ v1 收录（默认关闭 + 同意门控） | 免费无审批；debug 端点做连通性自检是好设计 |
| Meta CAPI | ✅ v1 收录（默认关闭 + 同意门控） | 目标用户最高价值功能；**Graph 版本号必须是可过滤常量**，文档硬编码的 v19.0 已停止支持 |
| 通用 Webhook（HMAC 签名） | ✅ v1 收录 | 最廉价最有用；飞书/企微/钉钉/Slack 只是消息格式器，无审批 |
| FCrDNS 爬虫验证 | ✅ v1 收录（**默认仅记录不拦截**） | 原型有致命 bug：`gethostbynamel()` 只返回 IPv4，IPv6 爬虫全部误判为假 Googlebot → **全站 SEO 下架事故**；必须加 DNS_AAAA 正查且失败时放行 |
| MaxMind GeoLite2 | ⚠️ 可选附加（站长自填 Key，禁捆绑） | 见 §5.3 |
| AbuseIPDB | ⚠️ 可选附加（默认关闭） | 免费 1,000 次/日；其熔断+缓存设计是档案中最好的弹性模式，推广为统一 HTTP 客户端 |
| Matomo（自建） | ⚠️ 可选附加 | GPL 兼容，差异化隐私卖点 |
| TikTok Events | ⚠️ 延后 | 需企业账号，版本需常量化 |
| 搜索引擎蜘蛛 IP 段订阅 | ⚠️ 默认关闭，手动刷新 | 文档设计为无条件每 7 天自动外呼，违反"零默认外呼" |
| Google Ads 离线转化 | ❌ v1 放弃 | 需 Google 审批的开发者令牌 + 完整 OAuth2 应用；文档锁定的 v16 已 sunset；免费自托管插件无法交付 |
| reCAPTCHA | ❌ 放弃（用 hCaptcha 替代） | 已并入 Google Cloud 计费体系；欧盟多次认定加载即传输个人数据需事先同意 |
| IPQualityScore | ❌ 放弃 | API Key 放在 URL 路径里，会泄漏进日志 |
| proxycheck.io | ❌ 放弃 | 免费额度太小，与 AbuseIPDB 重复 |
| 会话回放（rrweb 类） | ❌ 不做 | 最高同意风险、最高存储、最高责任 |
| 一切云端子系统（cloud.antigravity.ai、License、mTLS、bloom 下发） | ❌ 删除而非禁用 | 免费版定位 + WP.org 对"休眠外呼代码"也会标记 |
| 广告拦截器规避的伪装采集端点 | ❌ 禁止 | 蓄意绕过用户隐私工具，审核视为欺骗 |
| 绕过 WP 引导的独立 `collect.php` | ❌ 禁止 | 用带令牌的 REST 路由替代 |
| `mu-plugins` drop-in / `auto_prepend_file` | ❌ 禁止 | 写插件目录外文件，审核必拒 |

## 8. 对 greenpng 的总建议（决策摘要）

1. **greenpng 从空仓库重新开始**，不从 agy-suite 复制代码。领域层的业务语义以文档形式继承进 `03-function-registry.md`，代码按本仓库规范重写。
2. **五大业务域全部保留**（用户已确认），但分阶段交付，路线见 `12-roadmap-free-v1.md`。
3. **技术基线**：PHP 7.4+ / WP 6.0+ / 零 Composer 运行时依赖 / GPLv2+（用户已确认）。注意：agy-suite 原型代码使用了 PHP 8.0 语法（`mixed`、`str_contains` 等），即使参考也必须降级改写，红线见 `AGENTS.md` §4。
4. **合规先于功能**：默认零外呼、第三方集成全部 opt-in、同意门控、WP 隐私 API，是 WordPress.org 上架的前置条件，不是 v2 事项。清单见 `08-wporg-compliance-checklist.md`。
5. **范围宣称纪律**：对外只宣称已实现并测试的能力。管理页从 19 页起步而非 40 页；生态适配只承诺"WooCommerce + 4 款表单插件 + 公开适配器 API"，不承诺 156 款。
